useful evidence from retired dated audits and component handoffs. It is not a new

build, mock, earlier candidate or cross-published ZIP does not certify later source,
Windows/physical ARM, production removal, human Activity or physical Push delivery.

## Findings carried forward

- Portable callbacks must use framework JSON/delegates across isolated plugin loads;
  Notifications requires an explicit accepted/duplicate audit acknowledgment, not a
  fallback success in another ledger. Bridge discovery requires the standalone
  Notifications owner marker, not merely Hub's old adapter.
- Native paper/text theme mismatch was found by screenshot review after layout-only
  checks passed. Current checks assert colors and skin overrides, not just overflow.
- Reset verification follows native Security's exact-token verdict, not enrolled
  factor counts, browser flags, an old successful HTTP request or an admin mirror.
- Local single-writer/transaction/HTTP-creation mitigations do not remove native
  internal-call allocation/policy races or permit automatic duplicate-ID repair.
- Current-schema migration-lock avoidance must verify the exact known migration set;
  never steal/delete locks or ignore pending/unknown migrations.
- Durable attempt generations, current requester/authorizer identity, managed-only
  rollback snapshots and fresh command projections are separate safeguards.
