## Native database boundary

- Plugin stores have separate data paths; the exceptional native write boundary is `plugins/account-hub/src/AccountHub/InviteNativeProvisioner.cs`. It inserts a reserved user ID with default native preferences/permissions in a transaction, disabled, non-admin and hidden. Later password/policy changes use native APIs. This avoids the enabled/passwordless interval of native `CreateUserAsync`, but depends on the pinned Jellyfin 12.2 entity/schema contract. Happy-path installed tests are not schema/concurrency certification.
  The adapter now refuses unreviewed native assembly versions/providers and pending native migrations before inserting. It does not apply native migrations. Boundary tests passed (104 Hub tests total); the earlier full root run predates this guard.
- **Unresolved native creation concurrency risk:** Jellyfin 12.2 `UserManager.CreateUserInternalAsync` allocates `InternalId` using `MAX + 1`; the adapter follows that convention inside its transaction. Native creation reads outside that transaction. The native model has unique username indexes but no unique `InternalId` index. The plugin must not add constraints, repair IDs or alter Jellyfin's schema to hide this risk. Concurrent native/plugin creation needs acceptance; passing a few attempts is not proof against all interleavings.
- **Unresolved policy lost-update race:** native `UserManager.UpdatePolicyAsync` replaces the full policy under its internal user lock. Plugin callers read/check non-admin state before calling it, outside that lock. A concurrent native administrator edit/promotion may be overwritten. Rechecking before the call narrows but does not eliminate this race. A supported conditional/managed-field native update boundary or an explicitly reviewed mitigation is required for strict administrator-exclusion/concurrent-edit guarantees. Do not use private native locks or extend direct database mutation as an unreviewed workaround.

## Disposable verification

`scripts/integration.mjs --v1-flows --database-safety` adds concurrent native/invite creation requests, abrupt process termination/restart, preserved native identity/policy and Hub revision checks, then clean shutdown. `scripts/check-fixture-databases.py` inspects the owned fixture via a read-only mount, with SQLite query-only mode: integrity, foreign keys and native internal-ID/normalized-name uniqueness. It never repairs or changes a database and does not print user rows.

These checks do not simulate every transaction boundary, disk-full/I/O failure, backup restore, supported platform, native plugin event failure or production workload. Results and unresolved findings are tracked in `docs/review-status.md` and `docs/v1-release-gates.md`.

The r3 all-plugin disposable run (`suite-integration-9f4f6183-9b8c-4f5c-b8dc-71415832c72f`) passed concurrent native/invite requests and abrupt-restart identity/policy/revision preservation. Its first offline inspection could not open a WAL database on a strictly read-only filesystem. The inspector now copies each stopped database and its WAL/SHM/journal family to ephemeral storage, still opens the copy in query-only/read-only mode, and never changes the mounted originals. A follow-up read-only inspection passed all five databases (Jellyfin, Hub, Bridge, Deletion Queue, SyncPlay), including foreign keys and native ID uniqueness. Earlier restart timeouts used a stale ephemeral Docker host port; logs showed successful Jellyfin startup, and the harness now refreshes that port. These were harness failures, not evidence of server crashes or corruption, and their original failures are not counted as passing complete runs.

## Server/integration review findings (not all fixed)

- **Fixed in source; installed recovery acceptance pending:** Hub and Bridge persist matching installation identities in a plugin-owned database table and adjacent marker. Missing databases with installation/key artifacts fail before creation; initialized connections use non-creating SQLite mode. Identity mismatches fail without rewriting markers. Legacy enrollment occurs after existing integrity/key checks; a crash after identity commit but before marker creation resumes the same identity. New targeted missing/mismatch/interruption tests passed; backup/restore and installed path-loss acceptance remain required. These tables/markers never touch Jellyfin's native database.
- **Fixed in source/tests; fault acceptance incomplete:** eager lifecycle/settings construction is deferred through guarded hosted-service wrappers. Generic-host tests cover real file/directory conflict and simulated permission denial without stopping the host. Actual installed Jellyfin startup with inaccessible storage is not yet certified; repair/restart is needed after deferred initialization failure.
- **Fixed ordering/recovery regressions; broader fault acceptance incomplete:** invite revocation/rotation is ordered against final enable/completion and non-active invite status is preserved. Persisted `recovering` can be explicitly resumed with a fresh password under the host-singleton provisioning fence, after verifying the same native account remains disabled/non-admin; no automatic replay or creation occurs. This assumes one Jellyfin host owns its data directory, not multiple processes sharing it. Regressions cover revocation during redeem/resume and a simulated persisted interrupted-recovery stage; installed termination at each effect boundary remains open.
- **Partial fix validated:** the older workspace policy path calls the canonical managed-field native adapter after snapshot persistence instead of applying its stale full snapshot through Lifecycle. The adapter re-reads native state/admin status at the effect boundary. The native full-policy API concurrency risk described above still remains; this is not an atomic compare-and-swap guarantee.
- **Partial fix validated:** Seerr audit retries use the persisted job transition timestamp instead of the adapter's current clock, and event identity includes that transition timestamp/error to distinguish explicit retries. Repeated cancellation is idempotent. The real Hub audit-adapter replay regression passed. Complete durable outbox transition/acknowledgement concurrency acceptance is still required; this narrow fix is not full Seerr acceptance.
- **Fixed in source/tests; installed fault acceptance pending:** Lifecycle schema v3 separates `SessionsRevokedAt` from uncertain password outcome. Successful remediation stops repeated revocation, a shared singleton effect fence prevents maintenance overtaking live password writes, and durable attempt ordering rotates bounded 50-record batches past failures. 80 Lifecycle tests passed, including 125-record fairness, ambiguity, restart and race/cancellation cases. No password effects are replayed. Multi-host shared-store use is unsupported; installed crash/I/O boundary tests remain open.
- **Medium:** Deletion Queue's full-state journal grows on heartbeats/evaluations without authenticated checkpoint rotation; normal long-running use can reach permanent storage/replay limits. Representative-size soak, rotation and restart acceptance are required.
- **Fixed in source/tests; installed injection incomplete:** CompositeWorker isolates operations/ticks and exposes per-worker health independently of foundational readiness. Fake-driven maintenance/delivery regressions passed; actual installed transient-I/O injection remains open. Worker-running status is not upstream-delivery certification.

The server audit was static/read-only. These are findings, not a claim that every interleaving was reproduced. Work-in-progress fixes are not accepted until tested, repackaged and rerun on installed fixtures.
